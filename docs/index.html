01 — Persistência

O agente lembra na próxima sessão. De verdade.

Injeção automática no system prompt + recall híbrido (memória vetorial + grafo tier 4). Cada sessão continua de onde parou — sem copiar e colar contexto.

500 sessões
Cache LRU por sessão
recall + turnCount com evicção automática
~30 ms
Daemon cache TTL
resolveDaemon memoizado, fail-open sempre
anti-loop
Curadoria isolada
sub-agente fire-and-forget, nunca bloqueia
◎

Recall sob demanda

Ativa após o 1º turno; compõe contexto só quando há texto real.

◐

Fail-open em tudo

Daemon fora? O plugin degrada silencioso, nunca quebra a sessão.

02 — Entendimento

Grafo que explica o código, não só lista arquivos.

Indexação assíncrona com polling até ready, PageRank hubs, busca com expansão N-hops e ContextBundle pronto para o LLM.

04 — Instalação

Um bloco. Um restart. Pronto.

Sem wizard, sem CLI extra. Cole no opencode.json e reinicie o OpenCode — o Bun resolve o resto via cache.

.config/opencode/opencode.jsonc 
// .config/opencode/opencode.jsonc
{
  "plugin": ["@allansantos-dev/opencode-memory"]
}
  1. 1

    Cole o plugin

    Em opencode.jsonc global ou do projeto. Não use file:// em prod.

  2. 2

    Reinicie o OpenCode

    O Bun instala em ~/.cache/opencode/node_modules/ e atualiza em latest no próximo restart.

  3. 3

    Valide

    Rode memory_status no chat. Se o daemon não estiver rodando, use memory_setup.

Ver no npm → opencode ^1.18.0 · Node ≥18 · mcp-memory-server via OPENCODE_MEMORY_DAEMON_URL ou memory_setup

05 — Contratos

Regras duras do plugin.

O que não muda entre versões. Leia antes de automatizar.

◈

Single plugin export

src/index.ts exporta um único Plugin (OpenCodeMemory). Default é alias.

◎

Sem runtime deps

Só type de @opencode-ai/plugin; tool e zod são externalizados no esbuild.

⬡

project_id nunca é path

assertSafeProjectId rejeita paths. Isolamento real por projeto.

⬔

Curadoria nunca bloqueia

Sub-agente fire-and-forget em session.idle, com cooldown 10 min e anti-loop.
